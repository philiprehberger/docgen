# CLAUDE.md

Project guidance for Claude Code when working in this repo.

## What this repo is

A portfolio-grade Document Generation API by Philip Rehberger. Two halves in
one monorepo:

1. **Laravel 13 API + dashboard** at the repo root — REST endpoints,
   templates/versions, async render pipeline via Horizon, MySQL persistence,
   Filament admin, Twig templating, Spatie/Browsershot (PDF), PhpOffice/PhpWord
   (DOCX).
2. **Next.js 16 docs + marketing site** under `web/` *(Phase 8 — not yet
   present)* — interactive OpenAPI reference (Scalar), conceptual guides,
   per-language SDK pages, downloads, live try-it console.

The whole thing is a sales artifact: it demonstrates that the same person
can deliver a production-shaped API *and* the docs *and* the SDKs *and* the
deploy story. Treat every file as something a prospective client might read.

## Conventions

- **No AI attribution.** No `Co-Authored-By`, no "generated by Claude," no
  AI mentions in commits, code, comments, anything.
- **OpenAPI is the source of truth.** Endpoints in `routes/api.php` conform
  to `openapi/spec.yaml` — not the other way around. CI runs Spectral lint
  + contract tests. When you add a route, add it to the spec first, then
  implement the controller to match.
- **MySQL on production, sqlite local.** No `jsonb`, no `tsvector`, no partial
  unique indexes. Idempotency dedup uses a separate `idempotency_records`
  table.
- **ULIDs for all IDs**, stored as `CHAR(26)`.
- **`Authorization: Bearer docgen_live_…`** (or `docgen_test_…` for sandbox)
  for auth. Keys are hashed at rest; the `last_four` and `prefix` are stored
  plaintext for display.
- **RFC 7807 problem details** for error responses (`application/problem+json`).
- **Twig templates are sandboxed.** The `SandboxExtension` runs with a strict
  allowlist — no `attribute()`, no function passthrough. Templates run as data.
- **No premature abstraction.** Three similar repositories beats a generic
  base class. Bug fixes don't need surrounding cleanup. Trust the framework.

## Repo layout

```
/                 Laravel root — php artisan works from here
  openapi/        Hand-authored OpenAPI 3.1 spec
  sample-templates/ Three reference templates (invoice, offer letter, certificate)
  web/            Next.js docs/marketing site (Phase 8 — separate deploy target)
  sdks/           Generated SDKs (TS, PHP, Python) — added in Phase 6
  infra/apache/   Canonical Apache vhost files (mirror /etc/apache2/sites-available/)
  infra/cron/     Crontab entries for the EC2 host (TTL cleanup sweeper)
  infra/supervisor/ docgen-horizon.conf
  scripts/deploy/ Atomic release-based deploy (cloned from webhook-relay)
  .local/         Gitignored secrets (e.g., production MySQL password)
```

## Output formats

| Format | Engine | Path |
|---|---|---|
| HTML | Twig (sandboxed) | Always shipped — same render that feeds PDF/DOCX |
| PDF | Spatie/Browsershot + puppeteer Chromium | Best CSS fidelity |
| DOCX | PhpOffice/PhpWord `Html::addHtml` | Honest fidelity — letters, invoices, contracts. Complex flexbox/grid layouts will look different. |

## Voice and tone (matches `~/projects/income-ops/CLAUDE.md`)

Marketing copy in the README, the docs site, and any case-study material
follows the same voice as the sales material in `income-ops`:

- Lead with diagnosis, not pitch.
- Concrete numbers over adjectives.
- Em-dashes, short declarative sentences, no hedging.
- No emoji in user-facing copy. No exclamation points.
- "Production-shaped" not "production-grade." (This is a portfolio demo;
  honest framing sells better than overclaiming.)

## Deployment

- **Both halves build locally and rsync to the EC2 host** (54.190.150.0).
  No CI-hosted builds, no Vercel.
- **Apache + Let's Encrypt** for SSL on both subdomains. Vhost edits go in
  `infra/apache/` *and* on the server — keep them in sync.
- **PM2 port 3006** for the Next.js docs site.
- **MySQL `docgen` schema** on the EC2 host. The DB password lives in
  `/var/www/docgen/shared/.env` on the server and in
  `.local/server-secrets.env` locally (both gitignored).
- **Chromium** ships via puppeteer (npm) in the deploy bundle; the
  EC2 host needs `libnss3`, `libatk-bridge2.0-0`, `libgtk-3-0`, `libxss1`,
  `libasound2t64`, `fonts-liberation`, `libdrm2`, `libgbm1`, `libxcomposite1`,
  `libxdamage1`, `libxrandr2`, `libxkbcommon0`.

## Things to avoid

- Don't render anything in the request path that exceeds `DOCGEN_SYNC_RENDER_TIMEOUT`.
  Fall back to 202 + poll.
- Don't bypass the Twig sandbox. The whole point is letting prospects paste
  templates without us validating each one by hand.
- Don't write SDK code by hand. Always regenerate from
  `openapi/spec.yaml` — the per-language ergonomics wrappers are the only
  hand-written layer.
- Don't run `php artisan migrate:fresh` against the production DB without
  asking.
- Don't serve rendered files from a public path. All output URLs go through
  `temporarySignedRoute`.
- Don't ship a half-finished feature. Three similar lines is better than a
  premature abstraction, and a missing feature is better than a broken one.
